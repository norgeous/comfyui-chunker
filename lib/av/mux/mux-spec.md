# Video Module Specification

## Environment
- Use `conda activate comfyui` to get PyAV
- use PyAV 17.0.0+
- read the docs at https://pyav.basswood-io.com/docs/stable/
- you must use pyav remuxing when possible
- do not use ffmpeg subprocess calls

## mux Function
- code inside `./mux.py`
- Concatinate multiple mp4 videos into one mp4, with optional overlap.
- inputs:
    - **videos**: List of 2 or more similar h264 aac mp4 file paths (required)
    - **overlap_count**: count of frames to overlap between consecutive videos (0 or more) (required)
    - **overlap_blend_mode**: (required)
        - older_only
        - linear_blend
        - ease_in_out
        - newer_only
    - **output_path**: Path to save the output mp4 file (required)
- process
    - open all videos with pyav, and gather all video and audio packets
    - create a new container with same settings as video 1, using `add_stream_from_template()` to create same streams https://pyav.basswood-io.com/docs/stable/cookbook/basics.html#remuxing
    - it's important to setup the all empty streams inside the output container before starting to add packets to prevent errors
    - calculate overlap_regions for frames
        - for older_only and newer_only, use `actual_overlap_count = overlap_count`
        - for linear_blend and ease_in_out, use `actual_overlap_count = overlap_count + 2`
        - if the overlap_count is 0, there is no overlap_regions
    - processing video packets from all source videos
        - itterate through each video packet
            - frames outside the overlap region use remux to cleanly add the frame into the output
            - frames inside the 2 adjacent overlap region are decoded, processed (blended according to overlap_blend_mode), then encoded back into packets and added to the output stream
    - processing audio packets from all sources
        - transform overlap regions from frame based to time based
        - itterate through each audio packet and decode into a new list of samples
            - samples outside the overlap region use remux to cleanly add the frame into the output
            - samples inside the 2 adjacent overlap region are blended according to overlap_blend_mode
            - then encoded back into packets and added to the audio output stream

## Testing setup
- generate source mp4 files to be muxed in `./test-source`
- Tests use 512x512, 15fps, 30 frames source videos
- test source videos have human-recognizable output (font size 48 numbers in each frame, drawn with PIL),
- Tests use 44100Hz sample rate sine wave at 50% volume, so it's not too loud - each source has a different frequency
- source 1 is a red background video, with numbers 1 thru 30 on the 1st line in top left of each frame. with 400Hz audio
- source 2 is a green background video, with numbers 1 thru 30 on the 2nd line in top left of each frame. with 500Hz audio
- source 3 is a blue background video, with numbers 1 thru 30  on the 3rd line in top left of each frame. with 600Hz audio
- source videos are generated by `./mux-test.py` at run time
- these are example source for the mux function - the function itself should not care about the type of data in the source videos, as in practice the source videos will contain more complex data than whats described here.
